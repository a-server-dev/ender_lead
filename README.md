# EnderLead 1.0.4 — Paper 26.3 / Java 25

EnderLeadでモブを捕獲し、**同じPaperサーバー上の別ワールド**でも解放できます。解放成功時にリードは壊れます。捕獲・解放はどちらも左右クリック対応（左クリックはメインハンドのみ）。

## Mercenaryプラグイン互換

**調査対象**: 非公開の `a-server-dev/Mercenary` リポジトリの `main`（2026-11-13時点）。このリポジトリへの書き込み・コミット・PR・設定変更は行っていません。

- Mercenaryの傭兵は通常モブではなく、**Mannequin本体 + 非永続の透明Snowman（AI）**で構成。
- 傭兵の管理情報（雇い主/階級/名前/価格/待機地点/食料）はMannequinのPDCに入っている。HP/装備/スキン等はエンティティデータで保持。
- 別にある `plugins/Mercenary/mercenaries.yml` は雇用中の傭兵の最終位置を記録している。EnderLeadは既存のMercenaryManager/MercenaryRegistryの処理を**呼び出すのみ**で、捕獲時に旧登録を消し、解放時に新しい個体を登録。
- `Mercenary` に依存するAPIは公開されていないため、専用のリフレクション互換層をEnderLead側に追加。Mercenaryが大きく更新された場合は安全のため捕獲・解放を拒否します。
- 傭兵の本体をクリックしても、透明な脳モブをクリックしても本体を回収。脳モブは直接格納せず削除/再構築する。
- 捕獲前に装備/食料GUIを閉じ、食事を中断し、メモリ上の傭兵情報をPDCへ保存します。
- **雇用中は元の雇い主本人のみ捕獲可能**。未雇用の旅の傭兵も捕獲できます。
- 待機中の傭兵は解放先を新たな待機場所とします。旅の傭兵の消滅タイマーは格納中停止します。
- メイド（`mercenary:maid`）とメイドの透明脳は、独自の `maids.yml` 索引があるためデータ保護を優先して捕獲しません。
- 傭兵解放時にMercenaryプラグインが無効または削除済みなら**解放せず、アイテムを保持**します。

**注意**: Mercenaryの管理処理に協調するため、通常のエンティティNBTだけの復元より多くを保存できますが、サーバークラッシュ直前のプレイヤー保存状態や他プラグインの独立したDBまでは100%保証できません。まずバックアップを取ったテストワールドで、雇い主・階級・武器防具・食料・待機・別ワールド移動を検証してください。Mercenaryを使うサーバーでは両方のプラグインが必要です。

## クラフト・操作

- **クラフト（形状不問）**: リード×1 + エンダーパール×5 → エンダーリード×1。
- **捕獲**: 空のエンダーリードを持ちモブを左または右クリック。左クリック捕獲では攻撃ダメージを取り消します。
- **解放**: 格納済みエンダーリードで地面などのブロックを左または右クリック。成功時にリード消滅・破損音が鳴ります。失敗時は消費しません。
- **管理者用**: `/enderlead give <プレイヤー> [1～16]`, `/enderlead reload`。
- 左クリックはメインハンドのみ、右クリックはメイン/オフハンド両対応。

## ボス・保護NPCの制限

ボス（ウィザー/ドラゴン）、設定ファイル記載の強敵、一定HP超のEnemy、保護タグ付きNPC、他人の雇用済み傭兵は捕獲不可。Mercenary互換を無効にする場合 `config.yml` の `mercenary.enabled: false` を設定。

## 保存・データ保護

- Paperの `EntitySnapshot#getAsString` をPDCに保持し、解放時に復元。
- 複製アイテム対策に `plugins/EnderLead/released-ids.txt` の解放済みID台帳を使用。このファイルは削除しないでください。
- 大容量NBTは `max-snapshot-chars` を超えた時点で捕獲を拒否します。
- `EntitySnapshot#getAsString` はPaperが将来の完全互換を保証する永続フォーマットではありません。バージョンを変更する前に格納モブを解放しバックアップしてください。
- **Velocityで接続した別Paperサーバー間の移動は未対応**（共有インベントリと台帳同期が別途必要）。

## IntelliJでのビルド

1. Java 25を指定し、Gradle 9.2.1以降を利用。
2. プロジェクトフォルダをIntelliJ IDEAで開く。
3. Gradle Tasks → `build` を実行。
4. `build/libs/EnderLead-1.0.4.jar` をPaperサーバーの `plugins/` に配置。
5. 同じサーバーで `Mercenary.jar` が有効であることを確認し、再起動。

GitHub Actionsでビルドする場合は**EnderLead用の別リポジトリ**にソースを置いてください。Mercenaryのリポジトリにコミットしてはいけません。

## pipi_pve（添付の 0.1.0）との互換性

`pipi_pve` が作成した敵・ボス・召喚モブ・乗り物・補助モブはエンダーリードで捕獲できません。

- エンティティのPDCにある `pipi_pve:*` のキーで識別します。
- 専用PDCがない戦闘中の召喚モブなどは、実行中の PvE `Run` のエンティティUUID管理情報で識別します。
- 同じ種類の通常の野生モブは捕獲できます（既存のボス・HP制限は適用）。
- PvE側のプラグイン・リポジトリを変更する必要はありません。
- PvE内部構造が変わり判定不能になった場合は、誤捕獲を防ぐためPvE稼働中の捕獲を禁止します。
